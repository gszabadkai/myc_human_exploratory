`myc_mouse`.** No model was fitted, no score computed, no estimate exists. Every

## 1. The stop condition, triggered

The brief says: *"Establish and report: how many exist in the expression object
already on disk, whether they survived whatever filtering built the current
analysis set, and whether they were excluded deliberately. If they are not in
the saved object, say so and stop rather than re-fetching from GDC without being
asked."*

**They are not in the saved object. Not in any of them.**

## 2. They exist, they are on disk, and no GDC fetch is needed

The exclusion happened at the first step of the upstream pipeline, and the


Its header carries **1,226 columns**:

|---|---|
| `01` primary tumour | 1,106 |
| `06` metastatic | 7 |
| **`11` solid tissue normal** | **113** |

**113 normals, exactly the number the declaration expected.** The data this
analysis needs has been on disk since 2026-08-28. **Re-fetching from GDC is not
required and is not proposed.**

## 3. The exclusion was deliberate, documented, and for an unrelated reason

`myc_human_validation/scripts/01_fetch_tcga_expression.R`, read-only, section 2,
*"Samples: primary tumours only, one per patient"*:

```r
keep       <- which(sty == "01")
counts_raw <- counts_raw[, keep, drop = FALSE]
```

with the stated rationale: *"Same INTENT as G2: primary solid tumour only, one
column per patient, so the expression and copy-number analyses stay aligned."*

**The normals were dropped to keep expression aligned with copy number, not
because anything was wrong with them.** That reason does not apply to E36, which
reads no copy number. The exclusion is a consequence of the validation study's
design, inherited by this repo through the snapshot.

## 4. What including them would actually cost

**It is not a matter of adding 113 columns.** The declaration already requires a
single joint scoring, and the brief anticipates that it *"re-scores tumours
too"*. The cost is larger than that:

1. **The normalisation changes.** The saved matrices are DESeq2 size-factor
   normalised **over 1,095 tumours**. Size factors computed over 1,208 samples
   are different numbers, so the tumour values themselves move - not just the
   GSVA scores computed from them.
2. **The whole expression layer has to be rebuilt**, following the upstream
   script's pipeline: invert the Xena log2 transform, round to counts, keep
   protein-coding, collapse to symbols deterministically, DESeq2 normalise, and
   VST. That is validation script 01 re-run with one line changed, but **it
   cannot be run there** - that repo is frozen and must never be written to. It
   would be a new numbered script in this repo producing a new snapshot.
3. **Every downstream quantity would need recomputing on the new matrix**: the
   MYC estimators, the OXPHOS arms on both instruments, `PROLIF_DISJOINT`, and
   the configuration. The frozen `STATE` constructor can be re-applied, but the
   scores it consumes would be new.
4. **E34's and E35's numbers would not be directly comparable** to anything
   produced this way, which is why the brief asks for the tumour quadrant
   movement to be quantified rather than assumed nil.

**This is a snapshot-building job, not an analysis step.** It needs its own
decision.

## 5. A design constraint the declaration did not anticipate

**All 113 normals come from patients who are already in the 1,095-tumour
analysis set.** Checked directly: 113 of 113 matched, 0 unmatched.

| | |
|---|---|
| normals | 113, from 113 distinct patients |
| whose patient is in the tumour analysis set | **113** |
| whose patient is not | **0** |

**So the comparison is inherently paired, and the declaration treats it as two
groups.** Nothing in sections 1-3 of the declaration accounts for pairing. Any
analysis that treats the 113 normals as independent of the tumours would be
wrong for every one of them.

This cuts two ways, and both belong in the decision:

- **It is a problem**: the normal-tumour comparison needs a paired structure, or
  at least patient-level clustering, and a reading rule written for two
  independent groups does not transfer unchanged.
- **It is also a gift**: a fully paired design is far stronger than an unpaired
  one for exactly this question, because each normal is matched to its own
  tumour on genotype, age and everything else constant within a patient.

It also sharpens the declaration's own caveat. **These are not normal breasts.
They are the uninvolved tissue of 113 breasts that grew a tumour**, which is
what the declaration means by field-adjacent - and here it is literal, since
every one has its tumour in the same analysis.

## 6. The positive control, named now, before any fit

The declaration makes this a **stop condition**, and the brief requires it named
in this commit. From E14's comparators, the ones with a splittable and clean
cytosolic half are: **Fe-S cluster assembly** (13 mitochondrial / 10 cytosolic),
**mitophagy** (16 / 22), **mitophagy PINK1/PRKN only** (14 / 17), and isozyme
pairs, which E14 built as a CEILING control and is therefore the wrong
instrument here.

**DECLARED PRIMARY CONTROL: Fe-S cluster assembly.** Its cytosolic half is the
constitutive CIA pathway, which is housekeeping and has the least reason of the
three to differ between normal and tumour.

**Reported alongside, both also named now: mitophagy, and mitophagy PINK1/PRKN
only.** Mitophagy is E14's own chosen comparator for the apoptotic machinery,
picked because *"its cytosolic members translocate on activation, which is the
same hazard `BAX`, `BID` and `BAD` carry"* - so it is the closest structural
match, even though autophagy has more reason than Fe-S assembly to differ
between normal and tumour.

**All three are named before any fit. Whichever is used, the stop condition
applies to the declared primary**, and promoting one of the other two after
seeing the result is exactly what this naming exists to prevent.

- **Nothing was downloaded**, and no GDC request was made or proposed.
- **Nothing was written to `myc_human_validation`.** The Xena file and script 01

## 8. The decision required

E36 cannot proceed on the data in hand. The question is answerable, the source
is local, and the work is a bounded snapshot rebuild - but it changes the
tumour-side numbers that E34 and E35 rest on, so it is not a step to take
silently.

Three further things would need settling if it goes ahead, none of them fatal:

1. **The paired structure** (section 5), which the declaration's reading rule
   does not currently accommodate.
2. **The epithelial-content estimate** the declaration requires. ABSOLUTE purity
   is tumour-only and does not transfer; a marker-score or deconvolution
   estimate would have to be built and justified in both tissue types.
3. **Whether the rebuilt snapshot replaces or sits beside `data/from_validation/`.**
   Two normalisations of the same cohort in one repo is a trap, and
   `CLAUDE.md`'s scale-discipline section exists because of exactly this class
   of error.
