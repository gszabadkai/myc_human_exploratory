## 5. Conventions introduced this session

- **Record per-element digests in the result note.** E33's note carries an md5
  for every non-timestamp element of its saved object, recorded from the dry run
  **before** the author's run. That is what made the object-by-object check
  possible; E32 could not do it, because its dry-run scratchpad was gone. The
  note also says a digest mismatch is not by itself a numerical difference - a
  package update can change a tibble's attributes - so **compare values before
  concluding anything**.

  exist.** Both E33 and E34 hit this - "the composite" in a repo that had none -
  and in both cases the answer was recorded in the data note, pre-data, with the
  rejected alternative and the reason. E34's rejected alternative mattered: an
  unsigned guardian arm would have been biased *towards* the licensing verdict.
