# Plan — `myc_human_exploratory`, phase 1

## Context

The validation study (`myc_human_validation`) is **complete and closed** at
`d3ac60e`. It tested one narrow, pre-registered hypothesis under strict rules,
found nothing supported, and its value is precisely that it was capable of
saying so. It does not go in the paper and it is not reopened.

The new question is different and openly exploratory: **how do MYC and OXPHOS
actually relate in human breast tumours, and how does the cell-death programme
sit on that plane?** Starting point Menegollo et al. 2024; datasets TCGA-BRCA
and SCAN-B. Aim doc:
`myc_human_validation/docs/human_MYC_BRCA_exploratory_analysis.md`.

The death axis is the mouse arm's own — the full modality breakdown (15 Tang
modalities) and the pro-death / pro-survival × apoptosis / CICD stratification —
taken from its **native human columns**, not projected. See §1.3; this is the
input the validation study refused, for reasons that do not apply here.

This needs the *opposite* posture from the validation repo — that repo's
CLAUDE.md forbids post-hoc hypotheses, which is correct there and actively wrong
here. Hence a separate repo rather than a branch.

**Two facts that shape the whole build:**

1. **TCGA's mitochondrial half is already scored.**
   `tcga_brca_mito_scores.rds` carries 18 arms on **four** instruments —
   `gsva_arms`, `mitopps_arms`, `content_arms` (log2 summed DESeq-normalised),
   `zmean_arms` — which is exactly "DESeq normalised values, MitoPPS and GSVA".
   The first result already exists: `rho(M_a, OXPHOS subunits) = 0.388`, with
   **mitoribosome higher at 0.590** and fatty-acid oxidation negative at −0.140.
   That last pair is already a question worth asking.
2. **SCAN-B has almost none of it** (script 17 saved 4 GSVA sets and mitoPPS for
   one arm), and **neither cohort has the death sets**. Those two gaps are the
   only substantial compute in phase 1.

### 1.5 `CLAUDE.md` for the new repo

Must state the exploratory posture **explicitly**, and carry forward only the
rules that still bind. Sections:

- **This is exploratory.** Nothing here is pre-registered. Findings are
  hypothesis-generating and must be labelled as such. Do not import a conclusion
  from the validation repo without checking whether it was pre-registered.
- **This is a human repo** — verbatim from the validation CLAUDE.md.
- **Scale discipline** — GSVA/ssGSEA want log (VST, `kcdf="Gaussian"`); mitoPPS
  wants linear DESeq2-normalised. Never share an input object.
- **Cohort-relativity** — GSVA is cohort-relative, mitoPPS is
  composition-dependent. Score each cohort in one run; **never pool scores
  across cohorts**, compare patterns.
- **R rules** — no `print(n=)` after `head()`; always `dplyr::count()`;
  ASCII-only strings; `if (FALSE)` sandbox block ending every script.
- **Workflow "Option A"** — Claude writes and edits numbered scripts; the author
  runs them in Positron. Infrastructure (git, snapshots, READMEs, docs) Claude
  may execute.
- **Section 2, the traps** — see §3 below, each written out with its number.

## 2. Scripts

Numbered `E00`–`E05` (the `E` prefix keeps them visibly distinct from the
validation repo's `00`–`17` if the two are ever open together).

### `E00_setup_packages.R`
Mirror of the validation repo's `00`. Package list, `DIR_*` constants,
`PATH_MITOCARTA`, `PROJECT_SEED`, `.ensure_dir`, snapshot-shape assertions.

### `E01_load_and_assert.R`
Load every snapshot; assert scales (`log_vst` / `linear_deseq2_normalised`) and
dimensions (TCGA 18,115 × 1,095; SCAN-B 18,153 × 3,207). Build one harmonised
per-sample covariate frame for both cohorts:

```
cohort | sample_id | PAM50 | ER | subtype_group | purity | leuko | age | grade
```

ER harmonised across cohorts (TCGA `er_call` Positive/Negative; SCAN-B
`er_call` 1/0). PAM50 label harmonised (`BRCA_Her2` → `HER2`). Purity and
leukocyte fraction are **TCGA-only and stay NA in SCAN-B** — never imputed.

Saves `results/frames.rds`.

### `E02_score_cohorts.R` — the one heavy script
Two jobs, because the snapshot is asymmetric: **SCAN-B needs the full
mitochondrial scoring** (it has almost none), and **TCGA needs the death sets**
(its 18 mito arms already exist, the death sets do not). Reuses, from the
snapshot: `arm_sets`, `covariate_sets`, `mito_paths`, `arm_universe_path`, and
`symbol_map`.

- **Symbol harmonisation first.** Rebuild the map over the full union
  (arm sets + MitoCarta pathways + estimators + Hallmark sets) using MitoCarta's
  `Synonyms` column, forward direction only, refusing candidates that are
  themselves current symbols and refusing ambiguity. **Assert agreement with
  `scanb_pheno.rds$symbol_map` on the overlap.** Without this, `OXPHOS subunits`
  covers 0.775 instead of 0.989.
- **GSVA** on `scanb_vst`, one batch, with the `.PIN_A`/`.PIN_B` half-matrix
  pins: 18 mitochondrial arms + `PROLIF_DISJOINT`/`PROLIF_STD` + Felsher-61 +
  **every death set from §1.3 that clears its floor** (6 CDC strata, 12 Tang
  modalities). One batch, because the pins only hold the universe within a call
  and a set scored in a different call is not comparable. The same batch is
  scored on TCGA so the two cohorts carry identical set definitions.
- **mitoPPS** on `scanb_linear`: pathway universe, `.mitopps_universe`, and
  `.mitopps_query` against the held-out universe for each arm — assert every
  universe-pathway arm reproduces its canonical value.
- **`content` and `zmean`** instruments, same definitions as script 07 §6.
- **MYC estimators**: `M_a` (Felsher-61 GSVA), `M_b` (CollecTRI-811 ULM via
  `decoupleR::run_ulm`), and **raw `log2(MYC)`** from the linear matrix. `M_c`
  (amplification) is TCGA-only — SCAN-B has no CNV.

Saves `results/scanb_scores.rds` (same shape as `tcga_brca_mito_scores.rds`) and
`results/tcga_death_scores.rds`. Expect ~15–25 min, dominated by GSVA on
SCAN-B's 3,207 samples.

**The TCGA mito arms are reused, not recomputed.** They came from a run whose
numbers are already published in the validation study, and E01 asserts three of
them. Re-scoring would risk a silently different answer for no gain.

### `E03_correlation_atlas.R` — the data layer
One tidy table, no plots:

```
cohort | instrument | myc_estimator | arm | stratum | n | rho | ci_lo | ci_hi | p | adjusted
```

- `instrument` ∈ {gsva, mitopps, content, zmean}
- `myc_estimator` ∈ **the 16 compendium signatures + `HALLMARK_MYC_TARGETS_V1` +
  Felsher-61 (`M_a`) + CollecTRI (`M_b`) + `log2(MYC)`** (+ `M_c` amplification
  in TCGA) — 21 estimators
- `arm` = the 18 mitochondrial arms (which **already include `mtDNA-encoded
  OXPHOS` and CI–CV separately**), plus the 13 mtDNA genes individually
- `stratum` = all, ER+, ER−, LumA, LumB, HER2, Basal, Normal
- `adjusted` = raw / purity+leuko (TCGA only) / proliferation-adjusted

Spearman throughout, with Fisher-z CIs. Saves `results/correlation_atlas.rds` +
a CSV.

**Two named sub-analyses, because both are already visible in TCGA and both are
first-order:**

**(i) Nuclear vs mtDNA-encoded OXPHOS.** MYC does not regulate them alike:

```
                        M_a      M_b    log2(MYC)   mitoPPS/M_a   mean per-gene
OXPHOS subunits       +0.388   +0.240    -0.032       +0.306         +0.205
mtDNA-encoded OXPHOS  +0.068   +0.011    -0.053       -0.088         +0.025
CI subunits           +0.330   +0.162    -0.060       +0.249
CV subunits           +0.405   +0.253    -0.005       +0.331
```

On the composition instrument the mtDNA arm goes **negative** while nuclear goes
+0.31 — MYC-high tumours appear to *de-prioritise* the mtDNA-encoded programme
relative to the rest of the mitochondrion. Per gene the 13 do not move together
(`MT-ND6` −0.154, `MT-ND5` −0.143 … `MT-CO2` +0.243), so they are reported
individually as well as as an arm. This is the nuclear/mitochondrial coordination
question and it deserves its own figure.

**(ii) The estimator panel.** The same correlation computed under all 21 MYC
estimators, ordered by proliferation entanglement (§1.4). If the MYC–OXPHOS
correlation decays monotonically as entanglement falls, it is proliferation; if
it survives `MYC_UP.V1_UP` (1.5%) and `BILD` (3.9%), it is not.

### `E04_figures_correlation.R`
- Scatter: MYC vs OXPHOS subunits, per cohort × instrument, with a fitted line,
  faceted by ER and by PAM50.
- Heatmap: 18 arms × instruments × cohorts, rho as fill — this is where "the
  mitoribosome beats OXPHOS" becomes visible.
- Complex breakdown: CI–CV as a small forest per cohort.
- A raw-vs-adjusted panel, so the purity and proliferation cost is explicit.

### `E05_celldeath_axis.R`
The death axis, built from §1.3 and scored **inside E02's single GSVA run** so
it is cohort-relative-correct. Three layers, deliberately distinct:

**Layer 1 — CDC strata (pro/anti × apoptosis/CICD × ±MITO).** From source A,
`pathway == "both"` contributing to both strata, as the mouse arm did. Sizes in
human symbols:

```
                              all    MITO
pro-death     apoptosis       502      39
pro-survival  apoptosis       584      41
pro-death     CICD             13       5
pro-survival  CICD              4       2
```

**Emission floor n >= 5 (the library's own rule), so `pro-survival CICD` (4) and
`pro-survival CICD MITO` (2) are NOT scored** — reported as named gene lists
instead. That is why the mouse arm emitted 6 `CDC_*` sets, not 8. `ambiguous`
and `unclassified` effects are excluded from scores and reported separately.

**Layer 2 — the 15 Tang modalities.** GSVA where n >= 15 (12 of 15); the three
below (`Parthanatos` 11, `Oxeiptosis` 10, `NETotic` 9) are carried as gene
lists, not scores.

**Layer 3 — gene-level overlay.** `family_pathway` labels (BCL2 family, BH3-only,
effector caspase, apoptosome, death receptor…) and the individual BCL2-family
genes `BCL2 BCL2L1 MCL1 BBC3 BCL2L11 BAX BAK1 BID`, as points on the MYC–OXPHOS
plane rather than as scores. This is what "overlaid on the correlation plots"
most usefully means at these set sizes.

Outputs: rho of every death measure against MYC, against OXPHOS, and against the
MYC×OXPHOS product, per cohort × instrument × stratum; and the MYC-vs-OXPHOS
scatter coloured by each death score.

## 3. Traps — write these into `CLAUDE.md` §2, each earned

1. **Correlation is not the interaction.** The validation study found the
   `MYC × OXPHOS` *interaction* on apoptotic priming is null. A strong
   MYC–OXPHOS *correlation* is entirely compatible with that. Different
   questions. Never present one as confirming or contradicting the other.
2. **Purity and immune infiltrate.** In TCGA `rho(OXPHOS subunits, purity) =
   0.214` and `rho(·, leukocyte fraction) = −0.158`. Breast is the worst TCGA
   tissue for this — adipose is OXPHOS/FAO-high, infiltrate carries its own
   BCL2-family profile. **SCAN-B has no purity estimate**, so report raw and
   adjusted in TCGA, raw only in SCAN-B, and say so on every figure.
3. **Every MYC activity signature is entangled with proliferation, by wildly
   different amounts.** 1.5% (`MYC_UP.V1_UP`) to 47.6% (`YU_MYC_TARGETS_UP`),
   with the validation study's M_a at 14.8% and `HALLMARK_MYC_TARGETS_V1` at
   23.5% (§1.4). Never report a MYC–OXPHOS correlation from a single signature.
   Report the panel, ordered by entanglement, and the proliferation-adjusted rho.
4. **MYC mRNA is not MYC activity, and the difference is total.** In TCGA
   `rho(log2(MYC), OXPHOS subunits) = -0.032` against `+0.388` for the activity
   signature. A reader plotting MYC expression against OXPHOS sees nothing. Both
   are reported, and the gap between them is itself a result.
5. **The four instruments disagree, by a lot.** `rho_instruments` across arms
   runs 0.24 (lipid metabolism) to 0.94 (mtDNA). Instrument choice is not
   cosmetic; report all four or justify the one.
6. **mitoPPS is blind to level by design.** It answers "is OXPHOS *prioritised*
   relative to other mitochondrial programmes", not "is OXPHOS high". Never
   compare mitoPPS values across cohorts — only patterns.
7. **SCAN-B's symbols are a 2014 UCSC build.** 19 of 89 `OXPHOS subunits` genes
   are pre-2018 ATP-synthase names. Never score SCAN-B without the symbol map.
8. **mtDNA-encoded genes are held separately** and never pooled with
   nuclear-encoded subunits — expression-scale skew.
9. **CICD is thin and must not be over-read.** 13 pro-death and 4 pro-survival
   human genes. It is the axis of most interest and the weakest measured. Score
   only what clears n >= 5, show the genes individually, and never present a
   4-gene GSVA score as a programme.
10. **Two Tang sets are near-transcriptome-wide.** `Autophagy_dependent` (1,195)
   and `Ferroptosis` (935) are 6.5% and 5% of the matrix; a correlation with
   either is close to a correlation with general expression. Report them, and
   read them against a size-matched comparator before believing anything.
11. **The cell-death sets are human-native and must never be remapped.** Both
    sources carry first-class human columns and the upstream README says "Do NOT
    remap". Do not pass them through any ortholog function, in either direction.

## 4. Verification

**End-to-end anchor, and it is a real one.** The snapshot must reproduce a
number the validation study already published. After `E01`:

```
rho(M_a, `OXPHOS subunits` GSVA) in TCGA  ==  0.388   (script 07 arm_summary)
rho(M_a, `Mitochondrial ribosome`)        ==  0.590
rho(M_a, `Fatty acid oxidation`)          == -0.140
```

If these do not come out identical, the import is not faithful and nothing
downstream is trustworthy. `E01` asserts them.

Further checks:
- `E02` asserts every universe-pathway arm reproduces its canonical mitoPPS
  value (diff < 1e-8), and that the rebuilt symbol map agrees with
  `scanb_pheno.rds$symbol_map` on all shared symbols.
- The cell-death snapshot asserts on load: 1,232 rows, 1,232 distinct
  `human_symbol`, zero missing; `effect` and `pathway` take only their expected
  values; the 8 CDC strata come out at the sizes tabulated in `E05`; and the 15
  Tang files carry the sizes listed in §1.3. A changed count means the upstream
  file moved and the snapshot must be re-taken, not patched.
- **No ortholog function is called anywhere in the repo.** Grep for
  `mouse_to_human|human_to_mouse|ortholog` in `scripts/` should return nothing.
- `E02` asserts `OXPHOS subunits` coverage ≥ 0.98 in SCAN-B after harmonisation
  — it is 0.775 before, so this catches a missing map directly.
- Scale assertions in `E01`: VST max < 100, linear max > 100, both cohorts.
- Stratum sizes printed and compared: TCGA Basal 171 / ER− 237; SCAN-B Basal
  317 / ER− 475.
