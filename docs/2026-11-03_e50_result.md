## 4. Two findings about the graphics devices

**They concern previews and the reproducibility of files, not values.**

1. **R's default bitmap device here, quartz, darkens colours in a PNG.**
   - **The size:** `#624E3F` is written as `#4F3D30`.
   - **E49's tracked PNG previews show it.** This was checked: 4g's signature strip, stored `#EEB2AD`, reads `#E8A19D`.
   - **E48's PNGs went through the same default device,** so its previews are darkened in the same way. Both review packs show the darkened PNGs.
   - **Unaffected:** their PDFs, and E50's PNGs, which go through cairo.
   - **A guess, not tested:** the author's measured anchors are darker than Fig. 1g's source, which would fit a colour-managed reading.
2. **In one R session, a cairo PNG drawn after a cairo PNG and a `cairo_pdf` sets ggplot's multi-line text differently** from the first PNG.
   - **Reproduced in isolation.**
   - **E50 avoids it** by writing every PNG before any cairo PDF, and asks for a freshly restarted session.

**For future display scripts, two practices follow:**
- write PNGs with `type = "cairo"`;
- write all PNGs before any `cairo_pdf`, or use base `pdf()`.
