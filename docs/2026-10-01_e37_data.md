# E37 - the source, the pipeline, and the counts, before anything is built

**Nothing was downloaded. Nothing was written to `myc_human_validation` or
`myc_mouse`.** No matrix was rebuilt, no score computed. Every number below is a
column count, a barcode or a gene-set length.

---

## 1. The source is better than expected: the inversion is already done

The rebuild does **not** need the 138 MB Xena matrix, and does not re-do the
log2 inversion. Upstream cached its own intermediate, **before the sample
filter**, and that cache is on disk:

```
myc_human_validation/data/raw/tcga_brca_expression/tcga_brca_star_counts.rds
82 MB, READ-ONLY, in the frozen repo
```

| element | content |
|---|---|
| `$counts` | **60,660 genes x 1,226 samples**, storage mode **integer** |
| `$annotation` | 60,660 rows: `gene_id`, `gene_name`, `gene_type`, GENCODE v36 |
| `$averaged_col` | the 5 Xena-averaged columns, flagged upstream |
| `$sha256` | `058d7912...ceeedaa4`, the Xena source's checksum |
| sample types | `01` 1,106, `06` 7, **`11` 113** |

**This matters for trust, not just convenience.** The log2-to-counts inversion,
and its verification against four GDC per-file downloads, were done and asserted
upstream. The cache holds the *result*: integers. **The rebuild inherits a
verified inversion rather than repeating one**, and the single most delicate
step of the upstream pipeline is therefore not re-performed on my side at all.

**The GDC annotation file is also not needed** — the annotation travels in the
cache.

## 2. The filter reproduced exactly, then changed in one place

Upstream's rule, run here on the cached column names (counting only, nothing
built):

| step | type 01 |
|---|---|
| columns present | 1,106 |
| averaged columns dropped where the patient has a clean alternative | -5 |
| further duplicates dropped, keeping the lowest vial | -6 |
| **surviving** | **1,095** |

**1,095 — exactly the number in `data/from_validation/`.** The rule is
reproduced, not approximated, and that is the first evidence the rebuild is
faithful.

**The one change**, the same rule applied to type `11`:

| | type 11 |
|---|---|
| columns present | 113 |
| averaged among them | **0** |
| duplicate patients among them | **0** |
| **surviving** | **113** |

**Joint set: 1,095 + 113 = 1,208 columns.** Type `06` (metastatic, n = 7) stays
excluded, as upstream and as the declaration states.

### 2.1 A detail that ties two findings together

The 5 Xena-averaged columns are `TCGA-A7-A26J`, `A7-A26E`, `A7-A13E`,
`A7-A13D`, `A7-A0DB`, all type `01`. **Those are five of the six patients E33
found had their Menegollo forkscale and this repo's expression taken from
different vials.** The sixth, `TCGA-AC-A3QQ`, is a plain vial difference with no
averaging. The two observations are the same underlying fact — upstream
preferred a clean `01B`/`01C` over an averaged `01A` — seen from two directions.

## 3. The column key has to change, and why

Upstream renames columns to **patient** barcodes, which is safe when there is
one sample per patient. **With normals included a patient has two columns**, and
patient barcodes are no longer unique: **113 duplicates** in the joint set.

**DECISION: columns are keyed by the 16-character sample id** (`TCGA-A7-A0DB-01A`,
`TCGA-A7-A0DB-11A`), which is **unique across all 1,208** — checked. The object
carries a `sample_map` with `patient`, `sample_id` and `sample_type`, so the
pairing is explicit and recoverable rather than inferred from a barcode in
downstream code.

**Sample type is read from positions 14-15** of the barcode and from nothing
else, as the brief requires.

## 4. The rest of the pipeline, reproduced

Each step as upstream, on the joint 1,208:

| step | rule |
|---|---|
| annotation join | exact match on versioned ENSG; upstream stops below 95% matched |
| protein-coding | `gene_type == "protein_coding"`, non-empty symbol |
| duplicate symbols | collapse keeping the **highest mean count** row, not summing |
| low-count filter | `rowSums(counts >= 10) >= 10`, deliberately permissive |
| **normalisation** | **DESeq2 size factors over the JOINT 1,208** |
| **VST** | `vst(dds, blind = TRUE)` over the joint set |

**The low-count filter and the size factors are both computed over the joint
set, so both differ from upstream by construction.** That is the point of the
rebuild and the reason the gate exists: a gene kept or dropped differently, and
a size factor computed over a different sample set, move every tumour value.

**Two matrices, opposite scales, as `CLAUDE.md` requires**: linear
DESeq2-normalised for mitoPPS, VST for GSVA. They are saved separately and the
script states the scale at the top of each block.

## 6. A constraint the gate does not hit but E36 will

**`results/frames.rds` carries PAM50, purity and leukocyte fraction for the
1,095 tumours and for nothing else.** Normals have none of them, and none can be
manufactured: PAM50 is a tumour classifier and ABSOLUTE purity is tumour-only.

- **The gate is unaffected**: it is tumours only, and m1's covariates exist for
  all 1,095.
- **E36 is affected**, and the amendment already answers it: the normal-side
  adjustment is the `EPITHELIAL` marker score computed from the rebuilt
  expression, which exists for both tissues by construction. **No model in E36
  may ask for PAM50 or purity on a normal sample.**

## 8. The gate, operationally

E34's quantities are recomputed on the rebuilt snapshot **restricted to the
1,095 tumours**, which are the same patients in both snapshots, and compared
with the committed values in `docs/2026-10-01_e34_result.md`. The thresholds are
fixed in the declaration and are not restated here, so that there is one place
to change them and it is the one committed before any rebuilt value existed.

**The frozen `STATE` constructor is re-applied, not rebuilt.** Its median and
its `>` tie rule are internal and it takes its cuts from whatever vector it is
handed, so the quadrant remains its own call on the new scores. **The declared
assertions — Q3 == level 2, Q4 == levels 3 + 4 — are re-asserted on both
instruments and are a stop regardless of the numeric thresholds.**
