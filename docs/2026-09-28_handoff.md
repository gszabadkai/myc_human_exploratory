**It must travel with its three qualifications** (result note section 8):

1. **The marginals were already in `forkscale_models.rds`**, computed

## 4. Facts worth carrying that are not in the conclusions

1. **The GDSC download site is gone.** `cancerrxgene.org/downloads/bulk_download`
   returns HTTP 410. The data is still release 8.5 (27 Oct 2023), now at
   `https://cmp.cog.sanger.ac.uk/download/` and listed by
   `api.cellmodelpassports.sanger.ac.uk/download_files`. It can be fetched with
   `curl`, unlike the DepMap portal, which needs a browser.
2. **Drug names differ between platforms.** GDSC1 spells venetoclax
   `Venotoclax`; GDSC2 spells ABT-737 `ABT737` and leaves it out of the compound
   list; PRISM uses upper case. Grep the loaded tables for names; never assume a
   spelling.
3. **In cell lines, MYC activity and 8q24 copy number are uncorrelated**
   (`M_a` vs copy number `rho` = -0.037, n = 579). This is cheap evidence
   against using amplification as a proxy for activity.
4. **`forkscale_models.rds` holds the MB2 marginals as well as MB1's.** Anyone
   later citing it as "unread" or "MB1 only" should know that.
5. **In this repo, `M_c` is GISTIC amplification** (`M_c_call`, a discrete call
   with NAs), not MYC mRNA. F3-pre stored no `M_c` row for any fork.
6. **STATE is not built in this repo.** It exists only in the frozen repo, at
   `myc_human_validation/results/state_definition.rds`. E32 read it read-only.
7. **An R trap that stopped E32's first run:** inside `tibble()`, a newly created
   column shadows an outer variable of the same name, so a helper that uses
   that name receives the column instead of the data. Compute values before
   building the tibble, or don't reuse names.
