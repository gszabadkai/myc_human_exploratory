**The likely cause, and the fix** (later on 2026-11-05).
- **The cause:** the PDF read-back ran at the top level of the script. It left the PDF's raw bytes in the workspace (`PDF_TXT`, and the strings cut from it), and they are not valid UTF-8: the binary header, the soft hyphens and Symbol's multiplication sign.
- **Why it points to Positron:** it lists the workspace for its Variables pane once a script returns, and the crash came just then, each time.
- **Supporting evidence:**
  - E50 parses its PDF inside a function and never crashed;
  - the dry runs, under `Rscript`, which has no Variables pane, never crashed;
  - the saved results object holds no invalid string.
- **The fix:** the read-back now runs inside a function and returns only ASCII. Dry run 4 of the fixed script left 178 objects in the workspace, none holding invalid UTF-8.
- **It changes no output.** Dry run 4 reproduces the verified run: 8 of 8 digests, 26 of 26 assertions, and every file identical.
- **A re-run of the old version at 15:04 rewrote the tracked PDF**, changing only its two timestamps. The committed copy was restored.
- **Confirmed by the author:** the run of the fixed script at 15:14 did not crash. It matched the record again: 8 of 8 digests, 26 of 26 assertions, and every file identical. The tracked PDF's new timestamps were reverted, as before.

**After the run, the script's sandbox block was made self-contained** (the commit after `beead93`).
